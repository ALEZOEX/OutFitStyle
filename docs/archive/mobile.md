# Мобильная разработка для OutfitStyle

## Обзор

Этот документ описывает настройку мобильной разработки и процесс развертывания для приложения OutfitStyle.

## Технологический стек

### Flutter
- **Фреймворк**: Flutter 3.16.0+
- **Управление состоянием**: Riverpod
- **Навигация**: Go Router
- **База данных**: Drift (SQLite)
- **Сетевое взаимодействие**: Dio + Retrofit

### Платформы
- **iOS**: 14.0+
- **Android**: API уровень 23+ (Android 6.0+)

**Примечание:** Минимальный SDK Android 23 требуется для Firebase Analytics и современных библиотек.

## Поддержка работы без подключения

### Локальная база данных (Drift)
- Локальное хранилище на основе SQLite
- Автоматическая синхронизация
- Разрешение конфликтов
- Подход "сначала автономно"

### SyncManager - Менеджер синхронизации

SyncManager - это центральный компонент приложения, отвечающий за синхронизацию всех данных между локальным хранилищем и сервером. Он обеспечивает согласованность данных в автономном режиме и при подключении к интернету.

#### Архитектура синхронизации
SyncManager реализует многоуровневую архитектуру синхронизации:
- **Уровень мониторинга подключения**: Использует `connectivity_plus` для отслеживания состояния сети
- **Уровень управления синхронизацией**: Определяет, какие данные нужно синхронизировать и в каком порядке
- **Уровень выполнения синхронизации**: Использует `SyncWorker` для выполнения фактической синхронизации
- **Уровень отслеживания прогресса**: Отслеживает статус и прогресс каждой операции синхронизации

#### Как работает SyncManager
1. **Инициализация**: При запуске приложения SyncManager регистрирует слушатель состояния подключения
2. **Мониторинг**: Постоянно отслеживает состояние подключения к интернету
3. **Триггеры синхронизации**:
   - При восстановлении подключения запускается немедленная синхронизация
   - Периодическая синхронизация каждые 5 минут при наличии подключения
   - Ручная синхронизация по запросу пользователя
4. **Выполнение синхронизации**: Выполняет синхронизацию в определенном порядке - сначала настройки, затем гардероб, рекомендации, отзывы и отложенные изменения

#### Какие данные синхронизируются
SyncManager синхронизирует следующие типы данных:
- **Пользовательские настройки и предпочтения**: Персональные настройки стиля, предпочтения по погоде, настройки уведомлений
- **Элементы гардероба**: Добавление, обновление и удаление предметов одежды с учетом их свойств (температура, сезон, материал и т.д.)
- **Рекомендации**: История рекомендаций, статус избранного, рейтинги и отзывы
- **Отзывы и рейтинги**: Пользовательские оценки рекомендаций и обратная связь
- **Оффлайн изменения**: Все изменения, сделанные в автономном режиме, хранятся в очереди синхронизации до момента подключения

#### Обработка offline/online состояний
SyncManager эффективно обрабатывает переходы между онлайн и оффлайн состояниями:
- **Переход в оффлайн**:
  - Продолжает работу с локальными данными
  - Сохраняет изменения в локальной базе данных
  - Добавляет изменения в очередь синхронизации для последующей отправки
- **Восстановление подключения**:
  - Обнаруживает восстановление соединения
  - Автоматически запускает полный цикл синхронизации
  - Синхронизирует все накопленные изменения с сервером
- **Периодическая синхронизация**:
  - Запускает фоновую синхронизацию каждые 5 минут при наличии подключения
  - Обновляет локальные данные с сервера

#### Отслеживание прогресса синхронизации
SyncManager предоставляет подробную информацию о процессе синхронизации:
- **Прогресс по операциям**: Для каждой операции (настройки, гардероб, рекомендации и т.д.) отслеживается прогресс от 0.0 до 1.0
- **Текущая операция**: Можно получить информацию о текущей выполняемой операции (например, 'wardrobe', 'recommendations', 'complete')
- **Обработка ошибок**: При возникновении ошибок в одной операции синхронизации другие операции продолжают выполняться
- **Логирование**: Все операции синхронизации подробно логируются с различными уровнями (info, fine/debug, warning, severe/error)

#### Интеграция с другими компонентами
SyncManager тесно интегрирован с:
- **SyncWorker**: Выполняет фактическую синхронизацию через очередь отложенных изменений
- **Репозиториями данных**: Использует ProfileRepository, WardrobeRepository и RecommendationsRepository для синхронизации различных типов данных
- **Локальной базой данных**: Взаимодействует с Drift (SQLite) для хранения данных в автономном режиме
- **Сетевыми клиентами**: Использует удаленные источники данных для синхронизации с сервером

## Процесс развертывания

### Развертывание для iOS

#### Предварительные требования
- Учетная запись разработчика Apple ($99/год)
- App ID и профили подготовки
- Настройка App Store Connect
- Иконки (база 1024x1024)
- Скриншоты для всех устройств
- URL политики конфиденциальности
- URL поддержки

#### Автоматизация с помощью Fastlane
```ruby
platform :ios do
  desc "Загрузить новую бета-сборку в TestFlight"
  lane :beta do
    setup_ci if ENV['CI']

    # Сопоставление сертификатов
    match(type: "appstore", readonly: true)

    # Увеличение номера сборки
    increment_build_number(
      build_number: ENV["BUILD_NUMBER"] || latest_testflight_build_number + 1
    )

    # Сборка
    build_app(
      workspace: "ios/Runner.xcworkspace",
      scheme: "Runner",
      export_method: "app-store",
      output_directory: "./build",
    )

    # Загрузка в TestFlight
    upload_to_testflight(
      skip_waiting_for_build_processing: true
    )
  end
end
```

### Развертывание для Android

#### Предварительные требования
- Учетная запись разработчика Google Play ($25 однократно)
- Ключ подписи (ключ загрузки + подпись приложения)
- Настройка листинга в магазине
- Скриншоты и фирменная графика
- URL политики конфиденциальности
- Форма безопасности данных

#### Автоматизация с помощью Fastlane
```ruby
platform :android do
  desc "Загрузить новую сборку в Google Play Console"
  lane :beta do
    # Сборка
    gradle(task: "bundle", build_type: "Release")

    # Загрузка во внутреннее тестирование
    upload_to_play_store(
      track: 'internal',
      aab: '../build/app/outputs/bundle/release/app-release.aab',
      skip_upload_metadata: true,
      skip_upload_images: true,
      skip_upload_screenshots: true
    )
  end
end
```
