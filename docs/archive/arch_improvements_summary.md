# Архитектурные улучшения OutfitStyle

## Обзор

В этом документе описаны все архитектурные улучшения, реализованные в проекте OutfitStyle для повышения масштабируемости, надежности и производительности.

## 1. Перемещение ML-сервиса в отдельную директорию

### Проблема
ML-сервис находился внутри директории server, что нарушало принципы микросервисной архитектуры.

### Решение
- ML-сервис перемещен в отдельную директорию на уровне корня проекта
- Обновлены все пути в конфигурационных файлах
- Обновлены Docker и Kubernetes манифесты

### Результат
- Четкое разделение ответственностей
- Независимое развитие и развертывание сервисов
- Улучшенная масштабируемость

## 2. Внедрение Service Mesh (Istio)

### Проблема
Отсутствие централизованного управления сетевым взаимодействием между сервисами.

### Решение
- Внедрение Istio Service Mesh
- Настройка mTLS шифрования между сервисами
- Создание конфигурационных файлов для маршрутизации и политик безопасности

### Компоненты
- `istio/gateway.yaml` - маршрутизация внешнего трафика
- `istio/destination-rule.yaml` - политики подключения
- `istio/service-entries.yaml` - настройки взаимодействия между сервисами

### Результат
- Автоматическая безопасность трафика
- Централизованное управление сетью
- Улучшенная наблюдаемость
- Повышенная надежность

## 3. Внедрение Event-driven архитектуры

### Проблема
Синхронная обработка рекомендаций создавала узкие места и снижала производительность.

### Решение
- Внедрение Apache Kafka в качестве брокера сообщений
- Создание event contracts для рекомендаций
- Реализация publisher/consumer паттерна

### Компоненты
- `event-driven/contracts/event_contracts.go` - контракты событий
- `event-driven/publisher/publisher.go` - publisher событий
- `event-driven/consumer/consumer.go` - consumer событий
- `server/internal/infrastructure/eventing/` - интеграция с сервером

### Типы событий
- `RecommendationRequestedEvent` - запрос на генерацию рекомендаций
- `RecommendationProcessedEvent` - результат обработки рекомендаций
- `UserFeedbackEvent` - обратная связь пользователя

### Результат
- Асинхронная обработка рекомендаций
- Повышенная масштабируемость
- Улучшенная отказоустойчивость
- Лучшая производительность

## Технические характеристики

### Service Mesh
- mTLS шифрование между всеми сервисами
- Автоматическая ротация сертификатов
- Централизованное управление политиками
- Распределенная трассировка

### Event-driven архитектура
- Надежная доставка сообщений
- Поддержка масштабирования
- Обработка ошибок и повторных попыток
- Подписи событий для проверки целостности

## Метрики и мониторинг

### Service Mesh метрики
- Request Volume: количество запросов между сервисами
- Request Success Rate: процент успешных запросов
- Request Duration: время отклика
- Circuit Breaker: статус размыкателей цепи

### Event-driven метрики
- Topic Lag: задержка в обработке сообщений
- Events Published/Consumed: количество событий
- Processing Time: время обработки событий
- Failed Events: количество неудачных событий
