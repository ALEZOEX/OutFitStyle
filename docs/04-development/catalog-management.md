# Управление каталогом одежды

## NDJSON файлы

В проекте используются NDJSON (Newline Delimited JSON) файлы для хранения каталога одежды с архитектурой V2.

### Структура файла NDJSON_fixed.ndjson

Каждая строка файла содержит JSON-объект вида:
```
{"id": 90000001, "name": "Winter parka with hood in black color", "category": "outerwear", "subcategory": "parka", "gender": "unisex", "style": "street", "formality_level": 2, "warmth_level": 9, "min_temp": -25, "max_temp": 5, "season": "winter", "base_colour": "black", "usage": "daily", "materials": ["polyester","down"], "fit": "regular", "pattern": "solid", "icon_emoji": "🧥", "source": "synthetic", "is_owned": false}
```

### Использование файла каталога

1. **Для импорта в БД:**
   ```bash
   python scripts/seed_catalog_from_ndjson.py
   ```

2. **Для обновления через API:**
   - API позволяет добавлять/обновлять вещи из каталога
   - Используется при первоначальной инициализации системы

3. **Для ML-ранжирования:**
   - ML-сервис использует каталог для поиска кандидатов
   - Вещи фильтруются по нормам подкатегорий (subcategory_specs)

## Источники данных

### 1. Синтетические данные (NDJSON)
- ID вещей начинаются с 90000001
- Используются для начального наполнения каталога
- Параметры температур, теплоты и сезонности соответствуют нормам из subcategory_specs

### 2. Пользовательские вещи
- ID начинаются с 1
- Имеют source: "user"
- Имеют is_owned: true

### 3. Кастомные вещи
- Имеют source: "manual"
- Могут быть добавлены администратором

## Архитектура норм и подкатегорий

### subcategory_specs
Центральный компонент архитектуры Planner → Retrieval → Ranking:
- Содержит нормы теплоты, температурного диапазона, устойчивости к погоде
- Используется Planner'ом для формирования плана подбора
- Используется Retrieval для фильтрации кандидатов
- Используется Ranking для ML-ранжирования

### Приоритеты источников
1. user (личные вещи) - наивысший приоритет
2. manual (добавленные вручную) - высокий приоритет  
3. partner (партнерские данные) - средний приоритет
4. synthetic (синтетические данные) - низший приоритет

## Обновление каталога

1. **Для обновления из новых данных:**
   ```bash
   # Заменить NDJSON файл и запустить
   python scripts/seed_catalog_from_ndjson.py --force
   ```

2. **Для проверки целостности:**
   ```bash
   python scripts/validate_catalog.py
   ```

3. **Для генерации новых данных:**
   ```bash
   python scripts/generate_synthetic_clothing.py --count 10000
   ```

## Безопасность

- NDJSON файлы не содержат личной информации пользователей
- Все пользовательские вещи хранятся отдельно в БД
- Категории и подкатегории стандартизированы
- Используется безопасная загрузка с валидацией данных
