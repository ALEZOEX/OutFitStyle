## 🤖 ML-ПАЙПЛАЙН (4 блок — САМОЕ ВАЖНОЕ)

### 1. RETRIEVAL (фильтрация кандидатов)

```
Вход: температура, влажность, ветер, случай (occasion)

Правила фильтрации:
  • Если t < 5°C → исключить шорты, футболки
  • Если дождь → добавить плащи, зонты
  • Если вечер → формальный стиль
  • Если спорт → спортивная одежда

Выход: ~250 кандидатов из каталога (3000+ вещей)
```

### 2. FEATURE ENGINEERING

```
┌─────────────────────────────────────────────────────┐
│ ПОГОДНЫЕ (5 фичей):                                 │
│   temperature, humidity, wind_speed,                │
│   weather_code, season                              │
│                                                     │
│ ВЕЩИ (8 фичей):                                     │
│   category, subcategory, base_colour,               │
│   warmth_level, min_temp, max_temp,                 │
│   style, formality                                  │
│                                                     │
│ ПОЛЬЗОВАТЕЛЯ (6 фичей):                             │
│   style_preference, temperature_sensitivity,        │
│   formality_preference, gender,                     │
│   like_rate (история), body_type                    │
│                                                     │
│ КОНТЕКСТ (3 фичи):                                  │
│   occasion, time_of_day, location                   │
└─────────────────────────────────────────────────────┘

ИТОГО: 22 фичи
```

### 3. RANKING (CatBoost)

```
Задача: predict P(user likes outfit)

Модель: CatBoost Ranker (Gradient Boosting)
  • loss_function: YetiRank
  • iterations: 1000
  • depth: 6
  • learning_rate: 0.03

Валидация (hold-out 20%):
┌──────────────────────────────┐
│ Precision@5:    0.78         │
│ NDCG@10:        0.82         │
│ AUC-ROC:        0.85         │
│ MRR:            0.79         │
└──────────────────────────────┘

Сравнение с baseline (rule-based):
  • CatBoost vs правила: +23% по NDCG@10
  • Inference time: ~80ms (p95)
```

### 4. POST-PROCESSING

```
• Diversification: не более 2 вещей одной категории
• Вывод: Top-5 нарядов с score
• Кэширование: 10 минут (Redis)
```

## 🎯 КЛЮЧЕВЫЕ МЕТРИКИ (для защиты)

### Готовьтесь ответить на вопросы:

**ML:**
- ❓ Почему CatBoost, а не нейросеть?
  → Tabular data, CatBoost лучше работает с категориями,
    быстрее обучается, интерпретируем

- ❓ Как оценивали качество синтетики?
  → Сравнивали распределения категорий, сезонов,
    цветов с реальными datasets (Kaggle Fashion)

- ❓ Какие фичи самые важные?
  → temperature, warmth_level, style_preference,
    occasion (можно показать feature importance)

**Архитектура:**
- ❓ Зачем 3 слоя, а не монолит?
  → Разделение ответственности, независимое
    масштабирование ML, возможность замены ML
    без изменения бэкенда

- ❓ Почему Flutter, а не натив?
  → 95% общего кода, быстрее разработка,
    достаточно производительности для UI

- ❓ Как работает офлайн-режим?
  → Drift (SQLite) хранит вещи, рекомендации,
    настройки. SyncManager синхронизирует при
    подключении.

**Безопасность:**
- ❓ Почему JWT RS256, а не HS256?
  → Асимметричное подписывание, можно проверять
    токен без доступа к секрету (в микросервисах)

- ❓ Как refresh токены работают?
  → Access: 1 час, Refresh: 90 дней.
    При 401 клиент автоматически запрашивает
    новый access через /api/v1/auth/refresh
