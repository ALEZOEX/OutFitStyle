# Рекомендации по документации

## Типы документации

### 1. Встроенная документация (Go doc)
- Размещается непосредственно в коде
- Используется для документирования публичных функций, структур и пакетов
- Формат: комментарии перед элементами

```go
// UserService предоставляет методы для работы с пользователями
type UserService struct {
    // ...
}

// GetUser возвращает пользователя по идентификатору
// Возвращает ErrNotFound если пользователь не найден
func (s *UserService) GetUser(ctx context.Context, id domain.ID) (*domain.User, error) {
    // ...
}
```

### 2. Документация API
- Размещается в `docs/api/`
- Описывает endpoints, форматы запросов и ответов
- Может быть в формате OpenAPI/Swagger

### 3. Архитектурная документация
- Размещается в `docs/architecture/`
- Описывает архитектурные решения
- Диаграммы, паттерны, принципы

### 4. Руководства
- Размещаются в корне `docs/`
- `DEVELOPMENT.md` - руководство для разработчиков
- `DEPLOYMENT.md` - инструкции по деплою
- `SECURITY.md` - политика безопасности

## Стиль документации

1. **Ясность** - используйте простой и понятный язык
2. **Консистентность** - соблюдайте единый стиль во всех документах
3. **Актуальность** - документация должна соответствовать коду
4. **Примеры** - включайте примеры использования
5. **Структура** - используйте заголовки, списки, код-блоки

## Обновление документации

- Документация обновляется вместе с кодом
- При каждом значительном изменении обновляйте соответствующую документацию
- Используйте Pull Requests для изменения документации
