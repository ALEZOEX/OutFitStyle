# Рекомендации по организации документации

## Структура документации в проекте

### 1. Системная документация (автоматически генерируется)
- `internal/docs/` - сгенерированные файлы для Swagger
- Не редактируется вручную
- Обновляется через `swag init`

### 2. Архитектурная документация (руководства)
- `docs/` - основная документация проекта
- Организована по принципам, описанным в DOCUMENTATION_GUIDELINES.md

### 3. Встроенная документация (в коде)
- Комментарии в коде для GoDoc
- Обновляется вместе с кодом

## Рекомендуемая структура docs/

```
docs/
├── api/                    # Документация API
│   ├── endpoints/          # Описание конкретных endpoint'ов
│   ├── models/             # Описание моделей данных
│   └── examples/           # Примеры запросов/ответов
├── architecture/           # Архитектурные решения
│   ├── decisions/          # Архитектурные решения (ADRs)
│   ├── diagrams/           # Диаграммы (Mermaid, PlantUML и т.д.)
│   └── overview.md         # Обзор архитектуры
├── development/            # Руководства для разработчиков
│   ├── setup.md            # Установка и настройка
│   ├── workflow.md         # Рабочий процесс
│   └── testing.md          # Тестирование
├── deployment/             # Деплоймент
│   ├── production.md       # Продакшн деплоймент
│   └── staging.md          # Стейджинг деплоймент
├── guides/                 # Руководства
│   ├── contributing.md     # Как внести вклад
│   ├── coding-standards.md # Стандарты кодирования
│   └── security.md         # Безопасность
├── troubleshooting/        # Решение проблем
│   ├── common-issues.md    # Частые проблемы
│   └── debugging.md        # Отладка
├── README.md               # Главная страница документации
├── api.md                  # Обзор API
├── architecture.md         # Архитектурный обзор
├── development.md          # Руководство разработчика
├── deployment.md           # Руководство по деплою
└── security.md             # Политика безопасности
```

## Обновление документации

1. **При изменении API** - обновляйте комментарии для Swagger
2. **При архитектурных изменениях** - создавайте/обновляйте ADR
3. **При добавлении новой функциональности** - документируйте её
4. **При рефакторинге** - обновляйте соответствующую документацию

## Инструменты

- **Swagger** - для документации API
- **GoDoc** - для документации кода
- **Markdown** - для основной документации
- **Diagrams as Code** - для диаграмм (Mermaid, PlantUML)
