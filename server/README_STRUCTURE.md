# Серверное приложение OutfitStyle

## Структура проекта

```
server/
├── cmd/                           # Точки входа
│   └── server/                    # Основной сервер
├── internal/                      # Внутренняя реализация
│   ├── api/                       # HTTP API
│   │   ├── handlers/              # Обработчики HTTP-запросов
│   │   ├── middleware/            # Middleware
│   │   └── validators/            # Валидаторы запросов
│   ├── config/                    # Конфигурация приложения
│   ├── contracts/                 # Контракты для внешних сервисов
│   ├── core/                      # Бизнес-логика
│   │   ├── domain/                # Доменные сущности
│   │   ├── repo/                  # Доменные репозитории
│   │   └── application/           # Прикладная бизнес-логика
│   │       ├── repositories/      # Прикладные репозитории
│   │       ├── services/          # Бизнес-сервисы
│   │       └── planner/           # Алгоритмы планирования
│   ├── database/                  # Работа с базой данных
│   ├── infrastructure/            # Инфраструктурные компоненты
│   ├── logger/                    # Логирование
│   ├── middleware/                # Общие middleware
│   ├── pkg/                       # Вспомогательные пакеты
│   ├── service/                   # Вспомогательные сервисы
│   ├── telemetry/                 # Телеметрия
│   └── validation/                # Централизованная валидация
├── migrations/                    # Миграции базы данных
├── docs/                          # Документация
├── test/                          # Тесты
├── marketplace-service/           # Маркетплейс-сервис
├── ml-service/                    # ML-сервис
├── scripts/                       # Вспомогательные скрипты
├── Dockerfile                     # Docker-контейнер
├── go.mod, go.sum                 # Зависимости Go
├── Makefile                       # Команды сборки
└── STRUCTURE.md                   # Описание структуры
```

## Основные компоненты

### `internal/core/`
Центр бизнес-логики приложения:
- **domain/** - доменные сущности и бизнес-правила
- **repo/** - интерфейсы доменных репозиториев
- **application/** - прикладная бизнес-логика

### `internal/api/`
HTTP-интерфейс приложения:
- **handlers/** - обработчики HTTP-запросов
- **middleware/** - HTTP-middleware

### `internal/infrastructure/`
Инфраструктурные детали:
- Реализации интерфейсов
- Подключения к базе данных
- Внешние API-клиенты

### `internal/validation/`
Центральное место для валидации:
- Общие валидаторы
- Структуры ошибок валидации

## Архитектурные принципы

1. **Чистая архитектура** - зависимости направлены внутрь
2. **Разделение ответственности** - каждая директория имеет четкую цель
3. **Тестируемость** - архитектура позволяет легко тестировать
4. **Масштабируемость** - структура позволяет легко добавлять новые функции

## Тестирование

- Модульные тесты: `*_test.go` рядом с тестируемым кодом
- Интеграционные тесты: `test/`
- Тесты валидации: `internal/validation/test/`

## Документация

- API: автоматически генерируется через Swagger
- Архитектура: `docs/architecture/`
- Руководства: `docs/guides/`
- Структура: `STRUCTURE.md`, `TESTING_GUIDELINES.md`, `DOCUMENTATION_GUIDELINES.md`
