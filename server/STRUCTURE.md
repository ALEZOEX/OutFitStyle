# Структура проекта сервера

## Основные директории

### `cmd/`
- Точка входа в приложение
- `server/main.go` - основной исполняемый файл

### `internal/`
- Внутренняя реализация приложения (не для переиспользования вне проекта)

#### `internal/api/`
- Обработчики HTTP-запросов
- Middleware
- Валидация запросов (до бизнес-логики)

#### `internal/config/`
- Конфигурация приложения
- Загрузка переменных окружения

#### `internal/contracts/`
- Общие контракты (DTO) для взаимодействия с внешними сервисами (например, ML-сервис)

#### `internal/core/`
- Ядро приложения (бизнес-логика)

##### `internal/core/domain/`
- Доменные сущности
- Основные структуры данных

##### `internal/core/repo/`
- Интерфейсы доменных репозиториев
- Специфичные для доменных сущностей

##### `internal/core/application/`
- Прикладная бизнес-логика

###### `internal/core/application/repositories/`
- Интерфейсы прикладных репозиториев

###### `internal/core/application/services/`
- Сервисы бизнес-логики
- `*_test.go` - тесты для сервисов

###### `internal/core/application/planner/`
- Планировщики и алгоритмы (например, планировщик нарядов)

#### `internal/database/`
- Конфигурация и работа с базой данных

#### `internal/infrastructure/`
- Инфраструктурные компоненты (реализации интерфейсов)

#### `internal/pkg/`
- Вспомогательные пакеты, которые могут быть переиспользованы

#### `internal/validation/`
- Централизованная валидация
- `test/` - тесты для валидации

#### `internal/logger/`, `internal/telemetry/`, `internal/middleware/`
- Вспомогательные компоненты

### `migrations/`
- SQL-скрипты миграций базы данных

### `docs/`
- Документация проекта

### `test/`
- Интеграционные и end-to-end тесты

## Тесты

- Модульные тесты: `*_test.go` рядом с тестируемым файлом
- Тесты для сервисов: `internal/core/application/services/test/`
- Тесты для валидации: `internal/validation/test/`
- Интеграционные тесты: `test/`

## Принципы

1. **Разделение ответственности** - каждая директория имеет четкую цель
2. **Чистая архитектура** - зависимости направлены от внешних слоев к внутренним
3. **Тестируемость** - структура позволяет легко писать и находить тесты
4. **Документация** - архитектура проекта задокументирована здесь
