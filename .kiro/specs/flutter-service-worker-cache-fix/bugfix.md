# Bugfix Requirements Document

## Introduction

Flutter web приложение использует Service Worker для PWA функциональности, но агрессивное кеширование приводит к тому, что пользователи продолжают видеть старую версию приложения (build 04dcf98 от 9 марта 2026) даже после деплоя новой версии на сервер. Это критическая проблема, так как старый клиент несовместим с новым API и вызывает 401 ошибки. Пользователи вынуждены вручную очищать Service Worker и кеш браузера, что неприемлемо для production окружения.

## Bug Analysis

### Current Behavior (Defect)

1.1 WHEN новая версия Flutter приложения деплоится на сервер THEN браузер пользователя продолжает загружать старую версию из Service Worker cache вместо новых файлов с сервера

1.2 WHEN пользователь открывает приложение после деплоя новой версии THEN Service Worker не обнаруживает изменения и не инициирует обновление кеша

1.3 WHEN старый клиент из кеша пытается взаимодействовать с обновленным API THEN возникают 401 ошибки из-за несовместимости версий

1.4 WHEN пользователь перезагружает страницу (F5 или Ctrl+R) THEN Service Worker все равно отдает закешированную старую версию

### Expected Behavior (Correct)

2.1 WHEN новая версия Flutter приложения деплоится на сервер THEN Service Worker SHALL обнаружить изменения и обновить кеш с новыми файлами

2.2 WHEN пользователь открывает приложение после деплоя новой версии THEN Service Worker SHALL автоматически загрузить и активировать новую версию без ручного вмешательства

2.3 WHEN обновленный клиент взаимодействует с API THEN SHALL использоваться актуальная версия кода, совместимая с текущим API

2.4 WHEN Service Worker обнаруживает новую версию THEN SHALL уведомить пользователя о необходимости перезагрузки или автоматически применить обновление

### Unchanged Behavior (Regression Prevention)

3.1 WHEN пользователь работает с приложением в offline режиме THEN Service Worker SHALL CONTINUE TO предоставлять доступ к закешированным ресурсам

3.2 WHEN новая версия еще не задеплоена и текущая версия актуальна THEN Service Worker SHALL CONTINUE TO использовать кеш для быстрой загрузки приложения

3.3 WHEN пользователь впервые открывает приложение THEN Service Worker SHALL CONTINUE TO регистрироваться и кешировать необходимые ресурсы для PWA функциональности

3.4 WHEN статические ресурсы (изображения, шрифты) не изменились между версиями THEN Service Worker SHALL CONTINUE TO использовать их из кеша для оптимизации производительности
